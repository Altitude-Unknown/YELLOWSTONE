# Yellowstone / SHERPA / ICARUS Lab Notes

Date: 2026-06-30

## What we verified

- Ground YELLOWSTONE firmware sends the cutdown command correctly.
- Ground now reports command send status in the form:
  `STATUS,CUTDOWN_SENT,<seq>,sent,<count>,timeouts,<count>`
- Airborne YELLOWSTONE receives the LoRa command and prints:
  `Command forwarded to SHERPA: CUTDOWN seq=<seq>`
- ICARUS did not receive any cutdown packet during today's end-to-end tests.

## Important fixes made today

- Ground firmware was updated so cutdown LoRa transmit does not hang forever in
  `waitPacketSent()`. It now uses a transmit timeout and reports send counts.
- Airborne firmware currently includes the larger receive window used for
  command testing.
- SHERPA PCB wiring issue was found: the UART lines had been effectively
  `TX -> TX` and `RX -> RX`.
- User corrected the SHERPA PCB/wiring before leaving the lab.

## Current conclusion

The command path is confirmed through:

- Ground USB command input
- Ground LoRa transmit
- Airborne LoRa receive
- Airborne UART output toward SHERPA

The remaining failure point is after Airborne prints
`Command forwarded to SHERPA`, meaning the likely problem area is:

- Airborne-to-SHERPA UART electrical connection
- SHERPA UART pin mapping / bridge behavior
- SHERPA ESP-NOW transmit
- ICARUS ESP-NOW receive

## Recommended first retest tomorrow

1. Connect Ground YELLOWSTONE to laptop over USB.
